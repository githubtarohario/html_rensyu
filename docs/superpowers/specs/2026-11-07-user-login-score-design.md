# ユーザーID・ログイン・得点記録機能 設計

## 背景・目的 (Intent)

HTML練習サイト（[html_rensyu](https://github.com/githubtarohario/html_rensyu)、公開先: https://htmlrensyu.vercel.app）は現在、問題を解いて実行結果を見るだけの静的サイト。誰が解いたかの区別がなく、進捗はブラウザのlocalStorageにしか残らない。

複数人（友達・生徒など）が同じサイトを使い、それぞれの得点を記録・比較できるようにしたい。「得点」は「正解した問題の数」を意味する（issueで挙げたゲーム要素・ランキングの土台になる）。

## ゴール (Goals)

- ニックネーム/IDを入力するだけで「ログイン」でき、以後そのブラウザでは自動的にそのニックネームとして扱われる
- 各問題でコードを実行したとき、模範解答(`answer`)と比較して正解かどうかを自動判定する
- 正解した問題はユーザーごとに記録され、同じ問題を解き直しても二重に加点されない
- 得点（正解した問題数）がユーザーごとにサーバー側に保存され、ブラウザを変えても引き継がれる
- 全員の得点を比較できる簡単なランキング（リーダーボード）を表示する

## 非ゴール (Non-goals)

- パスワードによる本格的な認証（前の会話で「パスワードなしのニックネーム方式」を選択済み）
- なりすまし・改ざんの完全な防止（同じニックネームを他人が使う／ブラウザの開発者ツールで正誤判定を誤魔化す、は対策しない）
- 高度な学習分析（間違えた箇所の詳細な統計など）
- 問題内容そのものの変更・追加

## アンチゴール (Anti-goals)

- ログインが面倒になり、気軽に使えなくなること（新規登録フォームやメール確認は入れない）
- 採点が厳しすぎて、HTML的には正しいのに不正解判定になること（空白・引用符の種類・属性の順番の違いだけで不正解にしない）
- 既存の11問・highlight.js・problems.jsの構造を大きく壊すこと

## 制約 (Constraints)

- 現状はVercelにホスティングされた静的サイト（HTML/CSS/JS、ビルド不要）＋GitHubリポジトリ
- 開発者（依頼者）はこのサイトでHTMLを練習している段階なので、実装は複雑にしすぎない
- `problems.js` に既にある `answer` フィールド（模範解答）を正誤判定の基準にする

## 検討した作り方 (Approaches)

| 案 | 内容 | トレードオフ |
|---|---|---|
| A. Vercel Serverless Functions + Redis系KVストア（Upstash等、Vercel Marketplace経由） | 今のVercel/GitHub構成のまま拡張 | 設定がシンプル。ランキング（スコア順ソート）とも相性が良い |
| B. Vercel Postgres等のリレーショナルDB | テーブル設計・マイグレーションが必要 | 複雑な集計には強いが今回の規模には過剰 |
| C. Firebase（Firestore） | 新しい外部サービスが増える | リアルタイム更新は魅力だが、ニックネームのみのログインでは恩恵が薄い |

**選択: A**（本人承認済み）。既存のVercel/GitHubの仕組みのまま拡張でき、将来のランキング機能とも自然に合うため。

## 決定した仕様 (Decided)

- **ログイン方式**: 画面にニックネーム入力欄を表示し、入力したニックネームをそのブラウザの `localStorage` に保存する。以後そのブラウザでは自動的にそのニックネームとして扱う（ログアウト・切り替えボタンも用意する）。パスワードは持たない。
- **得点の数え方**: 「正解した問題の数」。同じ問題に複数回正解しても加点は1回のみ（初回正解時点で加点、それ以降は再実行しても得点は変わらない）。
- **正誤判定**: ブラウザ側（クライアントサイド）で、入力されたHTMLを `DOMParser` で解析し、各問題ごとに用意した判定ルール（必要なタグの有無・ネスト・テキスト内容など）で判定する。空白・改行・引用符の種類・属性の順番の違いは無視する「緩い」判定にする。**正解と判定された時だけ** サーバーのAPIを呼ぶ（不正解の実行ではAPIを呼ばない＝余計な書き込みをしない）。サーバー側では「呼ばれた＝正解」として信頼する（改ざん対策はしない。non-goalsの通り）。
- **バックエンド**: Vercelのサーバーレス関数（`/api/*`）を新設。データストアはVercel Marketplace経由のRedis互換KVストア（例: Upstash for Redis）を使う。保存するデータ:
  - ユーザーごとのハッシュ: 解いた問題のID一覧、得点、最終更新日時
  - ランキング用のソート済みセット（スコア順）
- **API（想定）**:
  - `POST /api/score` — `{ nickname, problemId }` を受け取り、未正解の問題なら加点して保存する（既に正解済みなら何もしない＝冪等）
  - `GET /api/leaderboard` — 全員のニックネームと得点をスコア順で返す（全件返す。件数が多くなったら上位N件への変更を検討。同点はニックネームのアルファベット順でタイブレーク）
  - `GET /api/me?nickname=...` — 自分の得点・解いた問題一覧を返す
- **ログイン時の反映**: ニックネームでログインした直後（および再訪問時、localStorageに保存済みのニックネームがある場合）に `GET /api/me` を呼び、サーバー側の「解いた問題一覧」を使って問題一覧に正解済みマーク（✓など）を付け、現在の得点を表示する。
- **ニックネームの検証**: 前後の空白を除去し、空文字は拒否、長さの上限（20文字程度）を設ける。表示時はHTMLエスケープしてXSSを防ぐ。**同じニックネームを別の人が使った場合、意図的に同一アカウント（同じ得点）として扱う**（パスワードなしという前の決定の帰結であり、対策はしない）。
- **UI**: ヘッダー付近に「ログイン中のニックネーム」と「現在の得点」を表示。正解すると軽い演出（色が変わる等）で知らせる。サイドバーまたは別セクションにランキング一覧を表示する。

## 確定事項（ビルダーチェック後の確認）

- **既存の進捗の扱い**: 移行処理は作らない。ログイン機能導入後は、全員が得点0・解いた問題0件からスタートする。
- **データストア**: Vercel Marketplace経由で Upstash for Redis を既に導入済み（`upstash-kv-cyan-saddle`、プロジェクト `html_rensyu` に接続済み）。接続情報は `vercel env pull` 等で取得した環境変数（`.env.local`、`.gitignore`済み）経由で利用する。

## ビルダーに委ねる部分 (Left to the builder)

- 11問それぞれの正誤判定の具体的なルール（どの属性・テキストまで厳密に見るか）
- Upstash/Vercel KVの具体的なセットアップ手順（パッケージ名、環境変数名は実装時のVercel側の最新の案内に従う）
- API・UIの詳細なエラーハンドリング（オフライン時・API障害時はローカルの得点表示のみにフォールバックする、等）
- ニックネーム入力欄・得点表示・ランキング表示の具体的なデザイン（既存の`style.css`のトーンに合わせる）
